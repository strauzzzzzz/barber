# Black Razor — PWA для записи в барбершоп / салон

Vite + React + TypeScript, чистый CSS. Бэкенд: Supabase (Postgres + RLS + Auth). Бот: Groq (tool calling) через serverless-функцию Vercel. Всё на бесплатных тарифах.

## Как это устроено

```
shared/config.ts    все тексты, лимиты, часовой пояс, имя модели Groq
shared/seed.ts      услуги, мастера, часы работы, тестовые отпуск/выходной → supabase/seed.sql
supabase/           001_init.sql (схема, RLS, защита от двойной записи), seed.sql
api/                Vercel-функции: chat, slots, bookings, catalog (+ _lib: слоты, запись, инструменты бота)
src/                клиент (Чат / Запись / Мои записи) и /admin (Supabase Auth)
public/             manifest, sw.js, offline.html, иконки
```

**Бот не знает расписание — он спрашивает базу.** Модель видит только инструменты `get_services`, `get_masters`, `get_free_slots`, `propose_booking`, `get_my_bookings`, `cancel_booking` (и `admin_list_bookings` — только для проверенного админа). Слоты считает одна функция (`api/_lib/slots.ts`): часы работы − перерывы − записи, дни отпуска/выходных пропускаются. Ею же пользуется ручная запись и финальная проверка при создании.

**Запись создаёт только кнопка.** У модели нет инструмента, который создаёт запись: `propose_booking` лишь проверяет слот и показывает карточку. Клиент нажимает «Подтвердить» → браузер шлёт `POST /api/bookings` (тот же endpoint, что и ручная запись) → сервер заново проверяет слот и вставляет строку. Это строже, чем «бот вызывает `create_booking` после подтверждения»: подтверждение нельзя обойти промптом. Дополнительная страховка: если в ответе модели есть время (`HH:MM`) или сумма, которых нет в данных инструментов, ответ заменяется.

**Двойная запись невозможна на уровне БД:** уникальный индекс `(master_id, starts_at)` и exclusion-констрейнт на пересечение интервалов (для активных статусов). Проигравший одновременный запрос получает `SLOT_TAKEN` и альтернативы.

Клиент идентифицируется токеном сессии в браузере (`x-client-token`), без аккаунта; телефон обязателен. Таблицы закрыты RLS: клиентский код не ходит в БД напрямую, только через API (service role на сервере). Админ работает через Supabase Auth, RLS пускает только email из таблицы `admin_emails`.

## Запуск локально (без Supabase и Groq)

```bash
npm install
npm run dev
```

Без переменных окружения включается демо-режим: данные в памяти из `shared/seed.ts`, «бот» — скриптованная заглушка (`GROQ_MOCK`). Чтобы проверить настоящего бота, положите `GROQ_API_KEY` в `.env.local`. Админка требует Supabase.

## 1. Supabase

1. [supabase.com](https://supabase.com) → New project (Free). Регион — ближайший к вам.
2. **SQL Editor** → вставьте и выполните `supabase/migrations/001_init.sql`, затем `supabase/seed.sql` (демо-данные; запускайте один раз).
3. **Authentication → Users → Add user**: email и пароль администратора (поставьте «Auto confirm»).
4. В SQL Editor добавьте этот email в список админов (в seed лежит `admin@example.com` — удалите):
   ```sql
   delete from admin_emails where email = 'admin@example.com';
   insert into admin_emails (email) values ('ваш@email.ru');
   ```
5. **Project Settings → API**: скопируйте `Project URL`, `anon public` и `service_role` (секрет!).

## 2. Ключ Groq

[console.groq.com](https://console.groq.com) → API Keys → Create API Key (бесплатный тариф). Модель задана в `shared/config.ts` (`CHAT.model = 'openai/gpt-oss-120b'`, запасная `llama-3.3-70b-versatile`). Список моделей со вызовом функций и актуальные лимиты — на странице Models/Tool Use в документации Groq; при смене модели правьте только config.

## 3. Деплой на Vercel

1. Залейте проект в GitHub → [vercel.com](https://vercel.com) → Add New Project → импорт. Framework: Vite (определится сам).
2. Environment Variables:

| Переменная | Где используется | Значение |
|---|---|---|
| `GROQ_API_KEY` | только сервер | ключ Groq |
| `SUPABASE_URL` | только сервер | Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | только сервер | service_role key |
| `VITE_SUPABASE_URL` | браузер (вход в /admin) | Project URL |
| `VITE_SUPABASE_ANON_KEY` | браузер (вход в /admin) | anon public key |

Переменные без префикса `VITE_` в бандл не попадают. Проверка после сборки: `npm run build && npm run check:bundle`.
3. Deploy. PWA заработает на HTTPS-домене Vercel. Админка: `https://ваш-домен/admin`.

## Что заменить под свой салон

| Что | Где |
|---|---|
| Название, слоган, телефон, адрес, часовой пояс | `shared/config.ts` → `SALON` |
| Шаг слотов, запас времени, горизонт записи, срок отмены/переноса (часы), лимит записей на клиента | `BOOKING` |
| Модель Groq, лимит сообщений в минуту, длина сообщения, длина истории | `CHAT` |
| Тексты бота, подсказки, тексты согласий | `TEXTS` |
| Услуги, цены, мастера, отзывы, часы работы, тестовые отпуск/выходной | `shared/seed.ts`, затем `npm run seed:sql` (или сразу в админке) |
| Часовой пояс в демо-записях seed | `scripts/gen-seed.mjs` (`Europe/Moscow`), если меняете `SALON.timezone` |
| Email админа | таблица `admin_emails` (шаг 1.4) |
| Название и цвета PWA | `public/manifest.webmanifest`, `index.html` (`<title>`, `apple-mobile-web-app-title`) |
| Иконки | `scripts/make-icons.mjs` → `npm run icons` или свои PNG 192/512/maskable 512/apple-touch 180 в `public/icons` |
| Реквизиты и текст согласия на обработку ПД | `TEXTS.consent*` — **согласуйте с юристом**, шаблон не является юридическим текстом |
| Напоминания | галочка согласия сохраняется (`reminders_ok`), но сама рассылка не реализована (после MVP) |

## Что проверить вручную перед запуском

- [ ] **Android (Chrome):** открыть сайт → меню ⋮ → «Установить приложение» → запуск с иконки без адресной строки.
- [ ] **iPhone (Safari):** Поделиться → «На экран Домой» → запуск с иконки, без адресной строки, статус-бар прозрачный.
- [ ] Офлайн: включить авиарежим → открыть приложение: видна оболочка, баннер «Нет сети», поле чата отключено с понятным текстом.
- [ ] В админке: выставить мастеру отпуск/разовый выходной → в чате спросить это время: бот не показывает окон в эти дни.
- [ ] Двойная запись: `node scripts/race-test.mjs https://ваш-домен` (три одновременных запроса → одна запись; тестовую запись отмените в админке).
- [ ] Лимит сообщений: отправить 11+ сообщений за минуту — появится «Слишком много сообщений. Подождите N сек.».
- [ ] Бот с реальной моделью: «хочу постричься завтра после 18» → карточки только с реальными временами; «покажи все записи» → отказ.
- [ ] Клавиатура на iPhone в чате: поле ввода не перекрывается, нижняя панель прячется.
- [ ] Отмена/перенос за меньше чем `cancelMinHours` блокируются с телефоном салона.

## Тесты

`npm test` — слоты (перерыв, записи, выходной, отпуск, особые часы), параллельные записи, отмена/перенос, бот (карточки, страховка ответа, лимит, история, права), и схема+seed в настоящем Postgres (PGlite): ограничения от двойной записи и `hit_rate`.

## Известные ограничения

- Сервер сопоставляет мастеров/услуги по данным БД, но **свободный текст модели про имена мастеров не проверяется** (проверяются только время и суммы). Список мастеров и карточки всегда берутся из БД.
- Лимит сообщений — фиксированное окно в минуту (на границе окна возможен короткий всплеск до 2×).
- `/admin` без сети не откроется (нужны Supabase и подгружаемый чанк).
- Нет отзывов как сущности: рейтинг и число отзывов — поля мастера (правятся в админке). Программа лояльности и рассылки напоминаний — после MVP.
- Статус «ожидает/подтверждена» для записей клиентов задаётся `BOOKING.defaultStatus`.
